Platform Architecture & Methodology

A rigorous open-source project intelligence and health analytics platform built with Django, PostgreSQL, Pandas, and the GitHub REST API.

System Data Pipeline 

User Request (Browser)
   ↓
Django Web Layer (URL Routing, Views, Forms)
   ↓
Analysis Service (Orchestration & Caching Layer)
   ├── GitHub API Service (Authenticated REST Client, Timeouts, Pagination Engine)
   ├── Data Normalization Layer (Payload Sanitization & Date Parsing)
   ├── Relational Persistence Layer (PostgreSQL / SQLite via Django ORM Transactions)
   └── Analytics Engine (Pandas Vectorized Aggregations & Time-Series Modeling)
             ↓

             ↓
  Deterministic Presentation & Visual Telemetry (Chart.js + Responsive UI)

5-Pillar Health Score Methodology

The OpenSourceLens health score is evaluated across five weighted engineering dimensions (0–100 points each) to produce a composite health index:

1. Activity Score

25% Weight

Evaluates multi-signal development cadence across four explicit components (0–100 points):

  • Recency (40%): Days since last push (≤3d: 40 pts, ≤7d: 36, ≤14d: 32, ≤30d: 28, ≤60d: 22, ≤90d: 16, ≤180d: 10, >180d: 4)
  • Frequency (30%): Commit volume scaled against analysis window days
  • Consistency (15%): Ratio of active commit days to total calendar days in window
  • Trend (15%): Velocity momentum comparing recent vs prior half of window

2. Issue Management Score

20% Weight

Measures triage velocity, resolution rates, and backlog scale (0–100 points):

  • Sample Resolution Rate (45%): (Closed Issues / Analyzed Issues) × 45
  • Turnaround Velocity (35%): Evaluated via median resolution time (≤24h: 35 pts, ≤72h: 28, ≤1wk: 22, ≤1mo: 15, >1mo: 8)
  • Backlog Hygiene (20%): Ratio of unresolved issues open >90 days relative to analyzed sample

3. PR Activity Score

20% Weight

Quantifies contribution throughput and merge velocity within the window (0–100 points):

  • Analyzed Merge Efficiency (50%): (Merged PRs / Analyzed PRs) × 50
  • Turnaround Velocity (35%): Median merge turnaround in hours/days (≤24h: 35 pts, ≤72h: 28, ≤1wk: 20, ≤1mo: 12, >1mo: 5)
  • Throughput Volume (15%): PR submission cadence scaled across the window period
  • Explicit caveat: Code review comment depth is not collected or simulated.

4. Contributor Diversity

15% Weight

Assesses distribution and concentration among analyzed contributors (0–100 points):

  • Contributor Base Depth (40%): Evaluates count of analyzed contributors (≥20: 40 pts, ≥10: 32, ≥5: 24, ≥3: 16, ≥2: 10, 1: 4)
  • Herfindahl-Hirschman Index (HHI) (40%): HHI = Σ (share_i)² (<1500: 40 pts, <2500: 30, <4000: 20, ≥4000: 10)
  • Lead Contributor Share (20%): Dominance of top author (<35%: 20 pts, <50%: 16, <70%: 10, ≥70%: 4)
  • Scope: Concentration measured among analyzed contributors returned by GitHub API.

5. Maintenance & Hygiene Score

20% Weight

Verifies metadata standards, licensing, and repository status via direct 0–100 normalization:

  • Documented Open-Source License: 30 points (validated via SPDX identifiers)
  • Active Status: 25 points (deducted if repository is archived / read-only)
  • Descriptive Project Metadata: 20 points (meaningful repository description)
  • Discoverability & Categorization: 15 points (defined repository topic tags)
  • Default Branch Hygiene: 10 points (standard main or master branch)
Composite Formula:
Final Score = round((Activity × 0.25) + (Issue × 0.20) + (PR × 0.20) + (Diversity × 0.15) + (Maintenance × 0.20))
Health Tiers: 85–100 Excellent | 70–84 Good | 50–69 Moderate | 0–49 At Risk. These categories are application-defined analytical classifications and are not universal software-quality standards.

Important Limitations & Analytical Scope

  • API Sampling: GitHub REST API queries analyze bounded batches of recent commits, issues, and PRs (up to configured pagination limits). Metrics reflect this analyzed sample within the selected window.
  • Analysis Windows: Velocity and cadence metrics depend directly on the chosen window (30D, 90D, 6M, 1Y).
  • Analytical Heuristics: Health scores and categories (Excellent, Good, Moderate, At Risk) are defined by OpenSourceLens for comparative analytics. They are diagnostic indicators, not universal software quality verdicts.
  • Data Privacy: OpenSourceLens exclusively ingests public repository metadata. No private repository content, personal passwords, or private keys are collected or stored. Configured GitHub tokens remain strictly server-side.
