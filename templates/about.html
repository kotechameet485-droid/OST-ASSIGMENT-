Platform Architecture & Methodology

A rigorous open-source project intelligence and health analytics platform built with Django, PostgreSQL, Pandas, and the GitHub REST API.

5-Pillar Health Score Methodology

The OpenSourceLens health score is evaluated across five weighted engineering dimensions (0–100 points each) to produce a composite health index:

1. Activity Score

25% Weight

Evaluates commit recency, push cadence, and development continuity.

  • Pushed ≤ 3 days ago: 96–100 points
  • Pushed ≤ 14 days ago: 88–95 points
  • Pushed ≤ 45 days ago: 75–87 points
  • Pushed ≤ 180 days ago: 55–74 points
  • Inactive > 180 days: ≤ 35 points
  • Bonus/penalty adjustments based on average commits per day

2. Issue Management Score

20% Weight

Measures triage velocity, resolution rates, and backlog scale.

  • Sample Resolution Rate: (Closed Issues / Total Issues) × 100
  • Turnaround Velocity: Evaluated via median resolution time (robust to extreme outliers)
  • Backlog Stagnation: Penalty applied for issues remaining unresolved for >90 days
  • Fallback: Open issues to stargazer volume scaling

3. PR Activity Score

20% Weight

Quantifies contribution throughput and review turnaround.

  • PR Merge Efficiency: (Merged PRs / Total PRs) × 100
  • Turnaround Velocity: Median merge turnaround in hours/days
  • Read-only state: Substantial penalty if repository is archived
  • Explicit caveat: Review comment depth is not collected or simulated

4. Contributor Diversity

15% Weight

Assesses maintainer community distribution and single-maintainer dependency.

  • Maintainer Base Depth: Evaluates count of active contributors (15+, 8–14, 3–7, 1–2)
  • Herfindahl-Hirschman Index (HHI): HHI = Σ (share_i)²
  • HHI < 1500: Well-distributed author share
  • HHI ≥ 2500: Elevated maintainer concentration indicator
  • Top 1 contributor share penalty when exceeding 80%

5. Maintenance & Hygiene Score

20% Weight

Verifies metadata standards, licensing clarity, and repository status.

  • Documented open-source license: +25 points (validated via SPDX identifiers)
  • Descriptive project purpose metadata: +20 points
  • Discoverability: Defined topics tags (+10 points)
  • Active status: -40 point penalty if repository is archived
  • Standard default branch (main/master): +5 points
Composite Formula:
Final Score = round((Activity × 0.25) + (Issue × 0.20) + (PR × 0.20) + (Diversity × 0.15) + (Maintenance × 0.20))

Important Limitations & Analytical Scope

  • API Sampling: GitHub REST API queries analyze bounded batches of recent commits, issues, and PRs (up to configured pagination limits). Metrics reflect this analyzed sample within the selected window.
  • Analysis Windows: Velocity and cadence metrics depend directly on the chosen window (30D, 90D, 6M, 1Y).
  • Analytical Heuristics: Health scores and categories (Excellent, Good, Moderate, At Risk) are defined by OpenSourceLens for comparative analytics. They are diagnostic indicators, not universal software quality verdicts.
  • Data Privacy: OpenSourceLens exclusively ingests public repository metadata. No private repository content, personal passwords, or private keys are collected or stored. Configured GitHub tokens remain strictly server-side.
